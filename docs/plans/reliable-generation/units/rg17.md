# RG17 — Verified webhook inbox

Read shared documents and evidence E8. Prerequisite: RG16. D12 defines provider scope.

## Goal

Generate the complete accept/store/process lifecycle for generic authenticated webhooks.

## Work

- Add a Webhook receiver capability in a Service with declared owned database and durable worker.
  Generate bounded raw-body ingress, authentication, durable inbox insert and acknowledgement.
- Implement one exact HMAC-SHA256 envelope using RG08: a timestamp and signature over timestamp
  plus raw bytes, fixed canonicalization and replay window, with constant-time verification and
  bounded multi-key verification. Specify header names/encoding precisely in the generated guide.
  This generic protocol is not advertised as Stripe or every provider's webhook format.
- Pure mapping supplies validated event identity/type/payload. It cannot replace verification,
  access secrets, ACK early or choose retry state. Identity/content conflicts have a documented
  refusal/quarantine result. Duplicate accepted deliveries return the proper stored acceptance.
- Dispatch accepted work through RG15/16. Product mapping selects a scoped command or safe declared
  external work. Completion/failure, retry and cleanup remain generated. Return 2xx only after
  durable acceptance; business completion can happen later.
- Add finite signature/body settings only with complete normal UI/chat/blueprint/generation
  consumers. An unsupported provider signature is an explicit gap, not a permissive verifier hook.

## Acceptance

Invalid/tampered/stale signatures and over-limit bodies never enter the inbox. Raw bytes are
unchanged by parsing. A lost 2xx followed by duplicate delivery produces one accepted identity.
Process loss after insert is recovered; transient processing failure retries; terminal failure
is visible. A conflicting body under an existing identity is not silently accepted as equivalent.
Two workers cannot commit under the same valid work generation.

## Emitted surface and checks

Receiver runtime/routes, inbox schema/grants, capability binding and pure product mapper scaffold.
Standard checks, signed-byte fixtures and acceptance/processing failure cases; full stack RG23.

## Not included

Stripe signatures/subscriptions, provider SDK adapters, public replay/admin UI or arbitrary code
executed before authentication.

**Commit:** `RG17: generate authenticated webhook ingestion and durable inbox processing`.
