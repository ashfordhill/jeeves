# RG07 — Versioned product migrations and SQL boundaries

Read shared documents and evidence E4/E6. Prerequisite: RG06.

## Goal

Product SQL has one migration history per owned namespace and a checked interface to generated
operations, without ad hoc ledgers in every module.

## Work

- Replace the new-contract re-run-file convention in generated `scripts/products.mjs` with
  ordered, checksummed product migrations and a shared ledger under the declared owner.
  Lock migration execution, reject changed applied content and roll back a failed migration.
- Execute product migrations with a role limited to the declared product namespace. Keep
  template-schema administration separate; verify accidental product DDL against protected
  template state is refused by the database, not just a comment or naming convention.
- Emit application-owned migration/query/command scaffolds plus a bounded declaration of product
  tables, named parameterized operations and published views. Validate declarations against the
  compiled owner/grant maximum; they cannot grant a new cross-owner dependency.
- Give product operations only their registered scoped handles. Policy hooks have no SQL handle.
  Reject declarations targeting reserved template schemas or transaction/lifecycle controls.
  Avoid claiming a complete SQL parser/security sandbox; database privileges remain enforcement.
- Document an explicit baseline/migration path for old re-runnable product SQL. Do not execute it
  against an existing app or infer a destructive schema conversion. Generated update refuses
  incompatible old declarations until the application's migration is supplied.
- Keep product SQL authored by the application; the generator owns migration bookkeeping and
  grants. Do not move QRWTY policy into Jeeves to make an example easier.

## Acceptance

Concurrent migrators apply each version once. A second start does not rerun applied SQL. An
edited applied migration refuses; a failed migration leaves no partial schema/ledger state.
Same-owner modules see shared declared state. Product code cannot obtain a protected-table or
foreign-owner handle. Existing application files survive update refusal unchanged.

## Emitted surface and checks

Product migration runner, ledger migration, SQL declaration/scaffolds and scoped operation API.
Standard checks and local database fixtures; defer real concurrent migration proof to RG14.

## Not included

No ORM, general schema designer, arbitrary SQL translation, destructive automatic migration or
live QRWTY database access.
