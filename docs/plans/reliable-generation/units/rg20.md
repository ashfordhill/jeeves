# RG20 — Concurrent session refresh and failure recovery

Read shared documents and evidence E9, including both arms' weaknesses. Prerequisite: RG19.

## Goal

Session refresh remains correct across replicas, temporary issuer outages and lost responses.

## Work

- Serialize rotation per session before calling the issuer and recheck stored token freshness/
  generation after acquiring coordination. Use a bounded database row lock for the first
  implementation; no global lock and no new coordination service.
- This is a deliberate internal protocol exception to ordinary product local transactions: the
  issuer call runs under the bounded per-session lock, and that transaction callback must never
  be automatically retried. Document timeout/lock consequences. Product hooks cannot invoke it.
- Distinguish definitive invalid/revoked grant from temporary network/provider failure and from
  uncertain rotation. A temporary failure does not indiscriminately revoke an otherwise valid
  session. Once new tokens arrive, record them under the internal completion budget even if the
  original browser disconnected, where possible.
- Define crash-after-provider-rotation behavior honestly. If the issuer invalidated the old
  refresh token and the new one was lost, reauthentication may be required; neither the lock nor
  an optimistic version check can manufacture the missing credential.
- Preserve revocation precedence, sealed-token rotation and expiry behavior. Prevent stale
  refreshed credentials from resurrecting a revoked session. Complete the session capability's
  runtime contract and failure descriptions.

## Acceptance

Two requests reaching the refresh boundary together cause one rotation and reuse its committed
result. A delayed successful issuer reply does not let a competing refusal revoke the winner.
Transient outage, definitive refusal and unknown rotation have distinct observable outcomes.
Revocation during coordination cannot be undone by a late result. Lock/provider timeouts and
shutdown are bounded. Tests inject time through internal test construction, not exported routes.

## Emitted surface and checks

Session-store/refresh runtime and its failure contract. Standard checks and adversarial ordering
tests against actual emitted code. RG23 proves coordination using two real processes/database
connections; no live managed issuer.
