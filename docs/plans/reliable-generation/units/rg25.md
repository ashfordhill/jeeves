# RG25 — Independent final review and bounded corrections

Fresh agent not involved in an implementation unit. Prerequisite: RG24. Read the approved
contract, concise handoffs, source and RG14/23/24 evidence; do not trust pass labels alone.

## Goal

Determine whether the fixed plan achieved its guarantees and correct defects within that scope.

## Review

- Trace representative operations from model/authoring through emitted code, product hook,
  persistence and recovery. Check actual generated artifacts, not only template source.
- Challenge cross-replica correctness, private-network authentication, least privilege, bypasses
  through callable paths, uncertain outcomes, stale-worker completion, session refresh and
  receipt retention. Check that policy hooks cannot accidentally acquire lifecycle controls.
- Confirm each mechanism is reusable with both fixture mappings and that no QRWTY policy became
  a framework default. Review code boundaries and change locality separately from test counts.
- Check saved-diagram/API migration, exported agent guidance and protected-file preservation.
  Locate any remaining old/new runtime duplication and any advertised but unimplemented support.
- Correct defects in existing assigned functionality when bounded. Add meaningful regressions
  for those defects and rerun affected checks. If correction changes an approved architecture
  choice or requires a new capability, stop and present the concrete issue to the owner.

## Acceptance and output

Write `evidence/rg25/review.md`: supported claims with evidence, corrected findings, remaining
limits and the release recommendation. Distinguish source inspection, tests run and historical
evidence. Do not claim universal superiority or certification from a finite case matrix.

Run standard checks after code fixes and relevant integration cases only. If no code changes,
record inspected checks/revisions and rerun only evidence that is missing or genuinely doubtful.
Any unresolved blocker prevents RG26 from calling the plan complete. No automatic RG27 or
open-ended improvement backlog is created.

**Commit:** `RG25: review and correct the reliable generation implementation`.
