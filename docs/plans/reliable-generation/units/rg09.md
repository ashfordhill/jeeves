# RG09 — Service identity and caller enforcement

Read shared documents and evidence E5. Prerequisite: RG08. Owner decision D6 applies.

## Goal

Every newly generated service-to-service call authenticates both its workload and any required
end user, with independent processes and per-operation allowed callers.

## Work

- Extend compiled call contracts, runtime target/guard adapters and identity setup assets.
  An identity provider can be selected for workload authentication without requiring a Browser
  session or an unrelated user Sign-in template just to provision it.
- Generate audience-bound workload acquisition/caching on the caller and verification/allowlists
  on the callee. Derive the maximum caller set from declared connections; an operation may narrow
  it. User identity is separate and never substitutes for workload identity.
- Private-network legacy links remain readable. For the new contract, missing supported issuer/
  caller configuration refuses the relevant generation with a concrete fix; no silent open call.
- Local tests use the existing local identity mechanism. Production credentials/issuer endpoints
  are validated configuration, not committed secrets or cloud provisioning. Keep the first issuer
  contract finite and explicit; no claim of compatibility with every managed identity product.
- Bound token/JWKS refresh, cache per process and preserve outage semantics. Forwarding uses RG03
  budgets and RG04 errors. Product code cannot choose audiences or replace attached credentials.

## Acceptance

Correct workload and user identities succeed; absent workload, wrong audience, disallowed caller,
expired token and user-only token fail. A private-network connection cannot bypass checks. Two
copies authenticate independently. Cached valid credentials allow their documented outage window;
no valid credential means refusal, not anonymous fallback. Missing setup is visible before export.

## Emitted surface and checks

Compiled caller contracts, HTTP target/guard, issuer/configuration/setup assets and reports.
Standard checks, verifier/client fixtures and mouse/chat refusal parity. RG14 runs real local
two-service authentication; no production identity calls here.

## Not included

Browser login, arbitrary credential plugins, cloud IAM or manually trusted headers.

**Commit:** `RG09: require workload identity on generated service calls`.
