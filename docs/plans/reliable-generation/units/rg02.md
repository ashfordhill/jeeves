# RG02 — Resource lifecycle and restricted extension API

Read shared documents and evidence E2/E3. Prerequisite: RG01.

## Goal

Give templates and handwritten modules one per-process construction/cleanup model, with a narrow
public API. Preserve independently runnable processes.

## Work

- Unify construction in `src/v2/{tile-processes,http-wiring,loop-wiring,client-wiring}.ts` and
  runtime `process.ts.template` / `features/service-resources.ts.template`. Reuse compatible
  clients across modules in one process, but never merge different credential/access scopes.
- A module's generated factory validates its declared configuration, initializes once, exposes
  its handlers/capabilities and registers close once. Validate template and stub settings before
  any connection. Cancel dependency waits on shutdown; configuration errors fail immediately.
- Implement stop-admission, cancellation, ordered drain and a documented final deadline. A hung
  hook cannot block termination forever. Partial startup failure closes opened resources.
- Establish the public extension API and application-owned contract directory. Product hooks get
  the bounded contexts described in contract section 3, not raw pools, credential readers or
  process-scope controls. Legacy signatures are explicit migration items under RG01.
- Add an offline generated-app boundary check, using tooling already installed: reject private
  cross-service imports, direct runtime/driver imports from hook bodies and forbidden effect
  APIs in pure policy hooks. Allow public contract/helper imports. This is an accidental-misuse
  check, not an adversarial sandbox. Put its script in exported package assets, not root scripts.

## Acceptance

Two modules share one compatible client and construct once before readiness; differently scoped
clients remain separate. A missing setting is reported before the first probe. A failed initializer
closes prior resources. Repeated shutdown is safe; a deliberately hung hook reaches the shutdown
deadline. Two process instances share no lifecycle memory. Forbidden and allowed import fixtures
are distinguished, and output names the violating file/API.

## Emitted surface and checks

Process files, runtime lifecycle/resource/public-API files, hook scaffolds, exported check script
and package script, extension guide. Standard code checks plus offline lifecycle/boundary tests;
do not create a new lint dependency or update root package/lock files.

## Not included

Request-budget propagation is RG03; public HTTP formatting is RG04. No arbitrary plugin lifecycle.
