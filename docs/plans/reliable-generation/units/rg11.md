# RG11 — Atomic cache primitives and recovery

Read shared documents and evidence E7. Prerequisite: RG10.

## Goal

Expose the shared-store operations needed for correct admission and mutable cache fills.

## Work

- Extend the generated Valkey adapter with bounded single-key atomic admission/window operations
  and compare-version writes. Use declared structured operations, not an arbitrary script/eval
  interface handed to application hooks. Define expiry semantics with server time where needed.
- Distinguish full client queue/saturation from a broken connection. A queue limit must not tear
  down a healthy connection and create an artificial multi-second outage for every caller.
- Integrate RG03 cancellation/budget/outcome rules and the shared lifecycle. Bound pending work,
  reconnect/backoff behavior and response validation. Do not conceal unavailable decisions as
  successful cache results.
- Keep optional-cache degradation separate from required admission. Implement the primitives;
  expose only the capabilities selected by RG12/13 rather than new generic user-facing knobs.

## Acceptance

Concurrent operations update one shared key atomically with the intended expiry. Older fills
cannot overwrite newer versions. Delayed replies do not extend absolute validity. Saturation
does not destroy a healthy client; genuine disconnect recovers. Malformed replies and expired
contexts fail with a classified outcome. No raw script or socket leaks through the public API.

## Emitted surface and checks

Valkey/runtime client primitives and scoped adapter types. Standard checks and adapter cases;
real competing clients are verified in RG14. No new provider or cache abstraction hierarchy.
