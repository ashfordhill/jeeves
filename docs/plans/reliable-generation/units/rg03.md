# RG03 — Operation context, deadlines and uncertain outcomes

Read shared documents and evidence E2/E6. Prerequisite: RG02.

## Goal

A generated request's budget reaches its dependencies; timeout is never misreported as proof that
an effect did not occur.

## Work

- Add a bounded operation context to the public API and thread it through HTTP/module adapters,
  database/cache/queue clients and declared external targets. Internal monotonic clocks stay local;
  forwarded budgets are remaining durations clamped by the receiver.
- Refactor runtime `module-clients.ts.template`, database/cache/provider adapters and wiring so
  templates and stubs use the same rules. Preserve current transaction connection ownership and
  poisoned-transaction/unknown-COMMIT safeguards.
- Support cancellation where the driver permits it; track outstanding operations until settled
  or the process drain bound. Prevent new operations after the context expires. Do not label a
  merely raced promise cancelled. Distinguish refusal, definite failure and uncertain outcome.
- Publisher options include validated bounded message attributes and stable message identity.
  An async delivery gets a new execution budget; do not propagate an expired request deadline
  into durable work. Correlation may propagate independently.
- External calls have bounded response bodies, declared destinations and typed outcomes. Product
  mapping cannot override credentials or choose an arbitrary origin. No automatic retry of a
  possibly completed mutation unless its capability explicitly supplies recovery/idempotency.

## Acceptance

A one-second request cannot start a fresh two-second dependency operation after its budget is
spent. A disconnected caller cancels supported work and prevents later dispatch. A late publish
or lost COMMIT response is represented as unknown and is not blindly retried. Attributes survive
publish; invalid/oversized attributes refuse. A stalled dependency does not hang shutdown. A queued
message still executes under its own budget after the original HTTP deadline has passed.

## Emitted surface and checks

Public context/outcome types, runtime clients, process/wiring calls and related adapters. Standard
checks plus deterministic adapter tests for deadline/late-result cases. Real failures are verified
at RG14/RG23; do not add cloud tests.

## Not included

No distributed clock synchronization, generalized retry configuration or new external provider.
