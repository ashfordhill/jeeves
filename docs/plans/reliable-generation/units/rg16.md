# RG16 — Scheduled work in an owning service or worker

Read shared documents and evidence E8. Prerequisite: RG15. D2/D5 apply.

## Goal

Scheduled maintenance/reconciliation has a generated home that works without incoming requests
and remains safe when several copies run.

## Work

- Add a Scheduled task module supported in Service and Worker hosts, using the common lifecycle
  and durable-work mechanism. Keep its setting surface finite: the interval, plus only a policy
  choice required by an implemented contract. Internal retry/fence bookkeeping is not a form.
- A separate worker uses the explicit owner/permission relationship from RG06. It does not gain
  a service's credentials by convention. A service-hosted task uses the same generated mechanism.
- Generate interval work identities from database time. Coalesce missed intervals to a current
  reconciliation tick, as the approved contract states. Competing schedulers insert the same tick
  once, while execution remains at least once and guarded by RG15.
- Run independently of request/message arrivals. Startup and shutdown own timers and running
  tasks. Bound task admission and execution; lease expiry alone must not permit stale completion.
- Update schema, catalog, inspector, blueprint, generation and chat together. Missing writable
  lease/work state or incompatible ownership refuses the binding, not a fake running timer.

## Acceptance

Both host kinds can schedule. Two copies do not multiply durable tick identities. Work outliving
one interval cannot commit under an expired fence. Killing a worker permits recovery. An idle
service still cleans up; downtime follows the documented coalescing rule. No perpetual unique
leader is required. A wrong-owner database cannot be connected for writes.

## Emitted surface and checks

Scheduled-task runtime/mounts, work binding, source/settings/normal commands and task scaffold.
Standard checks, fake-time plus database coordination tests and mouse/chat parity. RG23 supplies
the real competing-worker proof.

## Not included

Cron syntax, cloud scheduler provisioning, deployment CPU configuration or arbitrary timer hooks.

**Commit:** `RG16: generate durable scheduled tasks within explicit ownership`.
