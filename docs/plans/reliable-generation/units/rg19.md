# RG19 — Browser sign-in and session lifecycle

Read shared documents and evidence E5/E9. Prerequisite: RG18.

## Goal

Generate browser authentication and cookie-session mechanics with narrow application policy.

## Work

- Add the Browser session lead/binding and generated session/login-transaction schema, using
  declared owned state, RG08 sealed values and the common lifecycle/HTTP contract.
- Use a maintained OIDC implementation. Verify its supported API from primary documentation when
  selecting/pinning it; follow repository dependency rules. Changes belong to generated package/
  lock assets, not root files. Do not hand-roll OIDC protocol validation.
- Implement authorization-code+PKCE, one-use state/nonce/browser binding, bounded relative return
  paths, secure session cookies, login/callback/logout/session routes and CSRF. Support the finite
  issuer audience/offline-access parameters required by the declared integration, not arbitrary
  authorization URL injection.
- Coordinate CSRF with declared stateful browser cookies, including an application guest context
  when used. A cookieless route does not accidentally become authenticated. Product hooks receive
  identity facts, not token material, cookie secrets or raw session-table controls.
- Explicitly specify idle/absolute expiry and invalid-cookie behavior by route policy. Startup
  issuer outage affects login/readiness as declared; no production test-clock shortcuts. Expose
  subject-wide revocation for the owning service without generating account-deletion policy.
- Refresh/forwarding capabilities remain unavailable until RG20/21 supply their contracts; do
  not advertise incomplete token forwarding just because login works.

## Acceptance

Valid sign-in succeeds; state/nonce/PKCE mismatch and callback reuse fail. Session fixation fails.
Cookies have required flags; unsafe return paths fail. CSRF applies to protected mutations and
cannot be bypassed by a product body formatter. Logout/revocation/expiry have consistent results.
Issuer outage does not leak tokens or turn an invalid supplied identity into anonymous access.

## Emitted surface and checks

Session/OIDC runtime, schema/grants, generated issuer config, hooks/route adapters and source/UI
binding. Standard checks, protocol stand-ins and mouse/chat parity. Real local issuer proof RG23.

## Not included

User management UI, account-erasure saga, social-provider provisioning or refresh shortcuts.
