# RG10 — Complete local idempotent operations

Read shared documents and evidence E6. Prerequisite: RG09.

## Goal

Make correct replay ordering and atomic local mutation part of the generated operation boundary.

## Work

- Build a route/callable operation wrapper around the existing transaction and idempotency
  machinery, using RG05 contracts and RG07 scoped product commands. Framework order: authenticate,
  validate scope/key/input identity, recover committed result, perform new-work checks, commit the
  local mutation and replay record, render the result. Existing replays skip new-work admission.
- Keep scope/hash/conflict rules identical across HTTP and in-process calls. Handle concurrent
  identical requests and distinguish expired, conflicting, in-progress and committed records.
- Add sealed secret-bearing replay through RG08, with bounded response size and mandatory
  metadata. Keys and sealed payloads are never exposed in logs or across account scopes.
- Local mutation receives only scoped commands within one database transaction. No network handle,
  raw COMMIT/ROLLBACK or broad retry callback is supplied. Cross-database atomicity is refused.
- Preserve unknown-COMMIT semantics. Supply bounded expiry cleanup owned by the runtime; do not
  rely on another application request arriving to trigger it. Cleanup never removes active work.

## Acceptance

An existing successful response still replays when reputation/admission dependencies are now
unavailable. Same-key competing copies perform one local effect; changed input conflicts. A
cross-account replay fails. Mutation failure leaves neither a committed effect nor success replay.
A lost COMMIT response is recoverable. Sealed replay survives allowed key rotation. HTTP and
callable paths have matching behavior, and the product cannot inject an external effect callback.

## Emitted surface and checks

Idempotency/operation runtime, migration/grants, public scoped API and route bindings. Standard
checks, PGlite cases and deterministic lost-response tests; real contention is RG14.

## Not included

Provider payments or general distributed transactions. Durable external work begins at RG15.
