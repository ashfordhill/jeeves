# RG05 — Callable capabilities and stable contracts

Read shared documents and evidence E1/E3. Prerequisite: RG04.

## Goal

A custom operation can call a supported module through a typed, checked capability instead of
recreating it or importing its private implementation.

## Work

- Extend `module-generation.ts`, `studio-components.ts`, resolver/support and generator
  `module-stubs.ts` / `client-wiring.ts` / `http-wiring.ts` with a common callable binding.
  Replace the current template-part-unavailable path only for capabilities with an implemented
  callable adapter. Leave unsupported shapes as explicit gaps.
- Keep core capability construction separate from HTTP/consumer adapters. In-process invocations
  retain input/authorization/effect checks. HTTP exposure is explicit; linking a callable module
  does not accidentally mount a second public endpoint.
- Provide stable generated target handles for declared callee operations and one sanctioned
  application contract directory. Remove the need for handwritten `/modules/<id>` strings in
  newly generated callers. Product operation schemas remain bounded data contracts, not source
  expressions embedded in the diagram. No distributed schema registry.
- Make label-only renames preserve runtime identities and extension paths. Retain existing IDs
  on import; treat explicit identity changes as migration, not a rename. Update affected mouse,
  chat and rename expectations deliberately.
- Prove the binding with one existing simple capability/fixture. Rate limiting and cache-specific
  semantics are completed by RG12/13, not smuggled into this unit.

## Acceptance

A typed callable module is invoked without HTTP and with the same refusal semantics as its
transport adapter. Incompatible input/output/effect requirements refuse connection with a reason.
A label rename preserves target address, durable namespace and handwritten hook file. Shared
contracts import legally; private cross-service implementation imports fail the RG02 check.

## Emitted surface and checks

Capability contracts/handles, module slots, mount wiring and generated target addresses; relevant
normal authoring commands. Standard checks, schema/type/runtime binding fixtures and mouse/chat
parity. No blanket promise that every legacy template is now callable.

## Not included

No new service process, global registry server, language plugin system or arbitrary network proxy.

**Commit:** `RG05: bind callable capabilities through stable checked contracts`.
