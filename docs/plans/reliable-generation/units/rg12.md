# RG12 — Callable distributed rate limiting

Read shared documents and evidence E7. Prerequisite: RG11.

## Goal

Turn the existing Rate limiter vocabulary into a real reusable mechanism whose bound holds
across arbitrary process copies.

## Work

- Implement the Rate limiter lead/capability using RG05 binding and RG11 atomic operations.
  Generate the decision and retry interval. Choose and document one window algorithm; do not
  expose multiple barely implemented algorithms.
- Add only consumed finite limit/window settings, together with schema, normal authoring,
  inspector, blueprint and chat support. The cache dependency is required for this implementation.
- Product policy supplies a bounded key from validated facts. Address-based keys require a trusted
  address capability; do not infer trust from X-Forwarded-For. No edge-trust/deployment project.
- Fail closed when admission cannot be checked; no per-copy fallback allowance. The product error
  formatter may shape the refusal body, not erase the refusal or Retry-After.
- Integrate the local idempotent operation so a committed replay does not spend admission again.

## Acceptance

Two clients/process copies under one simultaneous burst cannot multiply the configured limit.
Expiry admits again according to the chosen algorithm. Outage is a typed unavailable refusal;
recovery resumes. Replayed completed operations spend nothing. Unsupported cache/provider/key
trust refuses with a useful reason. Mouse and chat produce the same supported settings.

## Emitted surface and checks

Limiter runtime, capability bindings, catalog/settings/authoring support and hooks for key policy.
Standard checks, offline algorithm/contract tests and a mouse check. RG14 proves shared Valkey
behavior. Do not copy the QRWTY per-process counter directory.
