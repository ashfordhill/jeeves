# RG14 — Independent foundation checkpoint

Fresh agent not involved in RG01–13. Read shared documents, their short handoffs and evidence E10.

## Goal

Confirm the foundation works across actual processes before durable work and sessions build on it.

## Work

- Review public API boundaries, ownership/grants, identity and generated transport composition
  against the approved contract. Do not read only the tests written by implementers.
- Add a small source fixture under `field-projects/generator-system/fixtures/rg-foundations/`:
  two independent service kinds, a same-owner worker role, scoped database state and Valkey.
  Use the existing generated-system harness; add a small `rg-foundations` suite registration
  in its existing suite map rather than another runner/framework.
- Run one bounded real local stack session with two copies of relevant processes. Assert:
  authenticated calls; wrong-caller refusal; precise reader/writer privileges; competing replay
  and admission; older cache fill refusal; concurrent migration; deadline/unknown-outcome behavior;
  dependency loss/recovery and bounded shutdown of a hung operation.
- Correct defects within RG01–13's approved scope. A new capability or changed guarantee returns
  to the owner. Do not invent a list of follow-on units to get the checkpoint green.

## Acceptance

The processes scale independently, no correctness mechanism relies on a single copy, and the
named cases have recorded expected/actual outcomes. Check actual database permissions and cache
operations, not only fake adapters. All accepted work/uncertain outcomes remain honestly classified.
The fixture and its hooks obey the same public boundary checks as application code.

## Output and checks

Fixture source/hooks, harness scenario/suite registration and `evidence/rg14/review.md` with
revision, tested cases, defects/corrections and limits. Standard code checks, then this targeted
integration suite once; rerun affected cases after fixes. Record clean Docker teardown.

## Not included
