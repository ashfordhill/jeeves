# RG04 — Uniform HTTP contract and operational visibility

Read shared documents and evidence E2. Prerequisite: RG03.

## Goal

Runtime, guards, module routes and template routes obey one public error/limit/health contract.

## Work

- Refactor runtime `http.ts.template`, `tile-http.ts.template`, `entry.ts.template`, guard and
  route-table adapters to use one error classification and a pure application body formatter.
  Keep status, retryability and mandatory headers under generated control. Preserve 405/Allow,
  validation errors and not-implemented distinctions without five application wrappers.
- Add the finite per-route body-limit/raw-body declarations needed for signed webhook ingress.
  Enforce limits before unbounded buffering. Formatter failure falls back to a safe body and
  never changes the selected status or leaks an exception.
- Separate liveness from readiness. Use RG02 startup/drain state and RG03 budget semantics.
  Add structured request completion/failure lines, request/correlation IDs and drain milestones;
  redact authorization, cookies, secrets and bodies by default.
- Apply the same adapters to existing mounted templates as well as stubs. Do not leave a parallel
  old HTTP error path for template routes. Update documentation only for behavior implemented now.

## Acceptance

The same application error shape reaches callers for guard refusal, route validation, overload,
deadline, invalid body and template failure, with correct status/headers. Formatting cannot turn
401 into 200. A raw signed body is unchanged; over-limit input is refused. Readiness falls during
drain while liveness retains its documented meaning. Logs correlate a request without credentials.

## Emitted surface and checks

HTTP/route/guard runtime, mount wiring, extension formatter scaffold and finite route declarations.
Standard checks and injected HTTP tests; no extra metrics/logging service. Any inspector control
added must have schema/form/blueprint/chat parity and a mouse check.

## Not included

Webhook authentication/storage is RG17. No tracing backend, audit features or product UI.
