# RG23 — Cross-domain composition and failure proof

Fresh agent. Read shared documents, evidence E10 and the accepted RG14 report. Prerequisite: RG22.

## Goal

Show the completed mechanisms work together with different product mappings and independently
scaled processes, rather than only as isolated helpers.

## Work

- Add two small source/hook fixtures under `field-projects/generator-system/fixtures/rg-*`:
  a link-like account/write/read flow and a media/catalog-like event/integration flow. Reuse
  generic acceptance lessons from QRWTY and existing YouTube hooks; do not rebuild either app.
- Each uses the ordinary exported API and passes boundary checks. Product differences are in
  policy/DTO/SQL mappings, not copied generated runtime code. Keep the fixtures to the operations
  needed for the following matrix, with no UI, billing or production deployment.
- Add a bounded `rg-mechanisms` suite using the existing integration harness. Run the fixture
  sessions sequentially with two copies of relevant API/worker kinds and controlled local
  dependencies, including the local issuer and a deterministic external-provider stand-in.

## Required observations

1. Concurrent session refresh produces one rotation; temporary issuer failure differs from
   definitive refusal and unknown rotation. CSRF and workload caller enforcement hold together.
2. A committed create replays despite a now-unavailable new-work check; duplicate admission is
   not spent. Shared limits do not multiply with copies. Mutable cache fills cannot regress.
3. Webhook storage precedes acknowledgement; kill after insert and restart another worker.
   Duplicate delivery is safe; changed-content identity conflicts; terminal failure remains visible.
4. Expire a work lease while the old worker is paused, claim with another, resume the old worker:
   the stale completion is rejected. Repeat the external step with a stable idempotency identity.
5. Kill a queue consumer after database commit but before ACK. Redelivery does not repeat the
   effect. Retention is checked at its boundary, cleanup runs without traffic, stopped heartbeat
   differs from idle, and date changes cannot bypass deduplication.
6. Drop/stall and restore database/cache/broker selectively; readiness, uncertain outcomes,
   retry/recovery and shutdown obey the contract. Inspect actual role permissions across owners.

Run standard checks and this targeted integration suite. Reuse RG14 cases where unchanged;
