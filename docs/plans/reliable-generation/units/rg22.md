# RG22 — Composition refusals and authoring parity

Read shared documents and evidence E1/E3/E10. Prerequisite: RG21.

## Goal

Finish the common composition contract so mouse, chat, preview and generation agree on exactly
which combinations the installed mechanisms support.

## Work

- Audit the capability requirements introduced by each prior unit. Keep one resolver/authoring
  source of truth, with emitter-backed checks; do not add an independent diagram-analysis engine.
- Cover incompatible effect classes; cross-database local atomicity; missing/foreign ownership;
  unsupported caller identity; invalid callable contracts; replay/receipt horizon mismatch;
  immutable versus versioned cache assumptions; unsafe external retry and incomplete lifecycle.
- Every refusal identifies the relevant modules/link and the missing supported capability in
  plain language. Existing saved designs remain readable. Incomplete product hooks remain explicit
  custom work; diagram validation does not pretend to inspect unwritten application semantics.
- Verify normal controls are only installed/consumed choices. A stub label remains truthful;
  do not infer from a raw settings schema that a normal control is offered. Remove any accidental
  new fields that have no actual consumer, rather than creating an Advanced section.
- Complete the generated application guide/checker: allowed hook forms, import boundaries,
  effect classes, migration steps and examples of accepted/refused code. This is the packet an
  application-writing agent follows, not a growing collection of contradictory prose tips.
- Confirm callable/public mounting, label renames and generation API version reporting across
  all installed capabilities changed by this plan.

## Acceptance

A compact table of valid and invalid compositions passes through mouse-equivalent commands,
chat tools, export preview and the CLI with matching outcomes. A refused edit has no partial
side effects. Unsupported fields cannot be set through chat. An unfilled hook is not certified
as complete. The resulting explanation points to an actual generated mechanism or declared gap.

## Emitted surface and checks

Resolver/support/normal-command rules, blueprint/report descriptions, extension guide/checker.
Standard checks, offline chat evals and mouse parity cases. Existing UI only; no new review screen.
