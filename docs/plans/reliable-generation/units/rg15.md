# RG15 — Durable work and fenced completion

Read shared documents and evidence E8. Prerequisite: accepted RG14 checkpoint.

## Goal

Provide a small reusable work mechanism that persists intent, survives process loss and prevents
an expired worker from committing stale results.

## Work

- Add generated work-table migrations and a runtime for accept, claim, renew, complete and fail.
  Records include stable work identity/input identity, state, attempt/backoff, holder and fence.
  Use database time and bounded batches; logs distinguish unavailable storage from poison work.
- Local completion checks holder/fence in the same transaction as the product mutation. Work
  state and the mutation must share a supported atomic database boundary; refuse cross-database
  atomic claims. Capability handles carry this scope; hooks cannot mint a fence or mark success.
- External calls occur outside that transaction through a declared integration capability, with
  stable idempotency identity or reconciliation. Persist uncertain outcomes for recovery. No
  provider without an adequate recovery contract is labelled repeat-safe.
  The initial remote mutation can target RG10's generated operation protocol; arbitrary external
  providers need an installed adapter. A test stand-in or an idempotency header alone is no proof.
- Add finite retry/backoff and durable terminal failure. Losing the lease stops new dispatch and
  invalidates later local completion. A terminated process leaves reclaimable work. Retention
  deletes completed eligible records, never accepted unfinished work.
- Expose a narrow work handler using product mappings/scoped commands. No arbitrary workflow
  graph, transaction completion, raw queue ACK or unrestricted client is given to the handler.

## Acceptance

Crash before dispatch, after external effect and before local completion all have defined states.
Another copy can reclaim expired work; the stale holder cannot commit. Repeated input is deduped;
same identity/different input conflicts. Terminal failure is visible. A timeout does not imply
the provider did nothing. An external effect with no safe recovery mechanism refuses support.

## Emitted surface and checks

Durable-work runtime/contracts, table/grants and scoped handler scaffold. Standard checks and
deterministic failure-point/PGlite tests; real process kill is RG23. Do not claim exactly-once
external execution or introduce a new coordinator service.
