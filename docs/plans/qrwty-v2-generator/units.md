## 2. Let the webhook receiver accept Stripe’s signature

Extend the installed receiver’s verification step and reuse its durable inbox and processing path. [Webhook runtime](../../../jeeves-generator/templates/local-v2/assets/src/runtime/webhook.ts.template) · [Receiver tests](../../../jeeves-generator/src/v2/webhook.test.ts)

**Deliver.** Add Stripe as a signature format alongside the existing Jeeves format. Verify the original body with Stripe’s SDK and the bound endpoint secret before decoding it for application code. Support the QRWTY limit of 256 KiB, a bounded signature age and an exact route that accepts provider calls independently of customer sign-in. Return 400 for an invalid Stripe signature, 413 for an oversized body and a retryable 5xx when the inbox cannot save it. Return success only after committing the verified event. Keep a stable event ID and content digest through processing and retries. For this selection keep completed IDs for 35 days and failed items until repaired. Existing generic receivers keep their defaults. The product hook decides what subscription state an event implies. [Installed receiver](../reliable-generation/evidence/rg17/protocol.md) · [Stripe verification and deliveries](https://docs.stripe.com/events/manage-webhook-endpoints#signature-errors)

**Prove.** Exercise the exported endpoint with SDK-signed test events, a body at the limit and one over, an altered body, an expired signature and a storage interruption. Observe durable storage before the first success. Retry after losing the reply and after a worker restarts. Deliver a duplicate to two copies, and check for one committed business effect. Check the same ID with conflicting content, out-of-order notices, the 35-day cutoff and retention of a failed event. Include a Stripe test-mode delivery when a designated test account is available. Record fixture and provider evidence separately. ## 3. Make click retention configurable

Trace both the public consumer declaration and the generated SQL cleanup. Scope each control to a module that can use it. [Receipt consumer](../../../jeeves-generator/templates/local-v2/assets/src/runtime/receipt-consumer.ts.template) · [Receipt lifecycle tests](../../../jeeves-generator/src/v2/receipt-lifecycle.test.ts) · [Scheduled task tests](../../../jeeves-generator/src/v2/scheduled-task.test.ts)

**Deliver.** Give the checked Event consumer settings for maximum replay delay and how long to keep counted IDs. Extend its existing 30-day limit in both validation and runtime to cover **31 days of replay and 35 days of receipts**. A receipt must last at least as long as a permitted replay. For a scheduled analytics cleanup with registered product SQL, supply **Keep daily totals (months)** as a validated argument actually used by the deletion query. A reusable binding can pass a cutoff to another product’s cleanup too. Keep SQL and the choice of table in the application. **Interval (seconds)** already sets how often the task runs. The QRWTY example uses 60 seconds and 13 calendar months. Preserve unconfigured consumers, existing Event counter behavior, older values stored in seconds and expiry promises for accepted work. [Installed receipt behavior](../reliable-generation/evidence/rg18/protocol.md) · [Requested settings](../../field-projects/qrwty/implementation-notes.md#choose-how-long-to-keep-clicks)

**Prove.** Commit the receipt and aggregate increment together. Exercise two consumers, repeat delivery after a lost acknowledgement, replay on day 31, the exact receipt expiry and a shorter setting applied to already accepted records. Advance a controlled clock across month ends and a year boundary. Use QRWTY’s UTC cutoff for daily totals and breakdowns. A row dated exactly on the cutoff survives that sweep. Show an idle job deleting precisely the expired totals, with recent totals and receipt rows intact. Change each setting independently and inspect the resulting rows. Check that changing only the timer changes when cleanup runs. Broker and archive retention are deployment requirements to record in the export.
