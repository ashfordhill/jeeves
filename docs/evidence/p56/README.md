# P56 — QRWTY architecture proof

The [QRWTY study](../../examples/qrwty-target.md) and five-block
[Inventory study](../../examples/inventory-architecture.md) are editable architecture intent.
The [package specification](../../build-plan-c4-evolution.md#p56--qrwty-architecture-proof)
defines the six scenario families. The staged mouse workshop and scripted chat use one operation
builder, exact contracts and normal validators/history. No source application, runtime or live
QRWTY design changes are part of this package.

QRWTY separates stable printed identity, encoded payloads, hosted content and artwork; models
owner/Studio/settings/reporting/staff features, tenant and API-key access, worker/export checks,
billing deduplication/entitlements, custom-domain ownership/TLS, abuse shutdown, redacted audit,
reporting retention/deletion/recovery and illustrative hosted placement. Main and named failure/
alternative paths reference real bindings and exact versions. Actors, components, contracts,
authoritative datasets and outcomes are traceable by identity.

Production workload/SLO/recovery values remain an assigned Unresolved decision. Review exposes
one unresolved objective and no manufactured capacity evidence. Expectations start Needs review;
recording agreement never records a runtime pass. Contradictory tenant/cache-failure/visit-loss
policies fail review even with an attempted decision waiver. Missing contracts reject an edit
atomically. Relevant changes expire expectation review. Planned capabilities still block Generate.

Inventory selects transactional-outbox stock work while QR visits deliberately choose bounded
loss. Real local-catalog publication/reuse proves exact version/content pins, required matching
interfaces and independent copies of portable pre-specialization tenant/delivery selections.
A copied best-effort informational channel never replaces the durable stock path.

scenario/decision references; save reusable selections before full product coupling.
