# P23: structured resource authoring

The [interim original-plan/product review](../../architecture-product-review-2026-10-31.md) selected ordinary resource configuration as the next gap. A focused list/detail editor now exposes the existing typed fields, owner/internal scope, required same-service relationships, finite CRUD and actual database binding. Stable IDs survive renames; IDs removed during a draft are reserved rather than accidentally reused. Save is one semantic operation. Cancel, undo/redo, reload and stale revision refusal preserve the design. Advanced contract configuration remains explicit.

Recipe boundaries come from the hash-verified server catalog. Provided resources/store are visibly fixed; additional independent resources remain editable. Domain extension GET/POST contracts, dependencies and acceptance references are preserved without applying schema defaults to their raw JSON. The shared dialog shell keeps Save/Cancel visible while long content scrolls.
