# P21 durable-delivery evidence

`@jeeves/durable-events@0.1.0` is an experimental original implementation of a transactional outbox and worker contract. Its consumer is a disposable non-QR inventory application using PostgreSQL 17. No live application, paid model or upstream runtime code is involved.

- Initial focused offline check: five tests passed, `.jeeves-work/runs/2026-10-31T06-30-04-799Z-unit-1889996a.*`. The final repository gate also includes the strengthened malformed-array case.
- Final `pnpm work run durable-events`: four real-Postgres conformance scenarios passed in 9.7 seconds, `.jeeves-work/runs/2026-10-31T06-34-36-064Z-durable-events-47815524.*`. Producer failure/conflicting key rolls back the business write and event; equivalent normalized keys reuse delivery identity; tenant scopes remain separate; two concurrent clients claim different events; expired tokens cannot acknowledge/fail/apply effects; finite failures and an expired final attempt become exhausted. A real database restart between effect commit and acknowledgement preserves one effect, and failed receipt/effect work rolls back before retry. Fixture containers and volume were removed.
- Source build/pack passed (`/tmp/p21-pack.log`). Native Node in a fresh temporary consumer imported the packaged root and browser-safe policy subpath without TypeScript/workspace resolution, instantiated the worker, performed its empty transactional claim and checked migration/policy exports (`/tmp/p21-package-smoke.log`). Its temporary directory was removed.
- The immutable artifact SHA-256 is `b0658fce9fbb692e317c54ded4c9b4fff3d4eb3c66b5d4b550947f67f60776fd`. [Release manifest](../../../artifacts/durable-events/0.1.0/manifest.json) includes source hashes; never replace this archive under version 0.1.0.
- The required final repository gate and diff review are recorded in the P21 handoff. No browser suite is required for this server component; no application UI changed.

Review tightened JSON normalization for sparse arrays with extra keys and prevented callbacks from issuing their own transaction control. Status metadata explicitly reports whether a database effect already committed; exhaustion must not be misread as proof that no effect occurred. The tests retain strict failure reporting and do not assert that every possible implementation defect has been eliminated.

Deferred: exhaustive retries/failure matrices, network delivery providers, ordering/fan-out, replay/retention UI, admission control, capacity/load/chaos, cross-process fleet and failover, security campaign and cloud deployment. A JavaScript handler ignoring cancellation can block its worker and be redelivered after lease expiry. These limits are part of the contract, not passing evidence.
