# @jeeves/http-pool 0.1.0

Experimental deterministic **local** HTTP pool definition. `createHttpPool({ serviceId, port: 8080, replicas: 2 })` returns a descriptor, HAProxy configuration/path and proxy Compose definition. Only two or three fixed instances are supported. It does not start containers, inspect application code or certify eligibility. Bind every named instance to the same reviewed generated API, shared database and public origin. Compose assembly and visual eligibility are separate responsibilities.

The default pair uses round-robin HTTP routing with `/ready` active probes (1s interval, two failures/two successes), Docker DNS refresh and at least one ready backend. `/health` describes the proxy process; `/ready` describes backend availability. Detection has a finite window and an in-flight request can fail during loss. The proxy explicitly disables retries and redispatch, closes backend HTTP connections between requests and passes application responses through. Ambiguous writes are not replayed. Callers still need domain-specific idempotency where required.

Bounds: proxy 0.5 CPU/128 MiB/64 PIDs, one HAProxy thread, 256 connections; each backend 64 active connections and 64 queued connections; 2s connect/queue, 10s request-header, 30s idle/server/tunnel, 5s keep-alive. These are finite ceilings/timeouts, not throughput or complete-request-duration guarantees. Proxy soft stop uses SIGUSR1 with 30s hard stop and 35s Docker grace. Backend execution/shutdown limits are separate versioned policy. Generated database pools should stay at five connections per instance; a pair/trio budgets ten/fifteen before other consumers and administration.

Host publication binds only 127.0.0.1. The proxy runs as uid/gid 99, with a read-only filesystem, temporary socket directory, dropped capabilities and no new privileges. Its local stats socket is read-only. Untrusted Forwarded/X-Forwarded-For/Host/Proto/X-Real-IP headers are removed; no original client-IP or trusted proxy-chain claim. Origin, cookie, CSRF, Authorization and request ID retain ordinary HTTP semantics. The current application runtime has no global authentication throttle. Do not expose this local profile as public ingress.

One proxy and one database remain failure points. No autoscaling, host failover, sticky sessions, TLS termination, distributed admission control, WebSocket/SSE contract, custom retry policy or arbitrary configuration is supplied. Arbitrary project features, process/filesystem state, timers, domain handlers and delivery workers require a separate reviewed eligibility contract. Read the [repository audit](../../docs/reference/local-http-pool-audit.md). Focused proofs are not bug-free, capacity, chaos or security certification.
