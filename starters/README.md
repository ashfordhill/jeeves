# Editable architecture starters

The default starting design is the **Streamly · video platform** architecture study ([walkthrough](../docs/examples/streamly.md), listed in [CATALOG.md](../CATALOG.md#streamly-video-platform)). It is a complete C1–C3 planned design with no runtime templates; the resource workspace below is the template-backed, generatable starter.

Choose **New project → Resource workspace** (or **Explore starting points** on an empty board) to create a separate project with accounts, private resources, typed forms, related records, paging and intentional C4 context. Choose a product name, tagline, visual preset and page size. Inspect resources/screens to change the actual model, then Generate with its baseline check. Supplied behavior needs no implementation model; additional business actions still need explicit contracts and implementation.

A starter is a versioned, hash-verified **editable copy** of a design and layout. `startedFrom` records its origin; it does not freeze the copied resources or certify the current application. Current template capabilities, generated ownership and verification determine what is supplied. A protected [product recipe](../recipes/README.md) also supplies fixed domain implementation/acceptance and has stronger core boundaries. A blank project supplies neither.

Registered snapshots are local reviewed files. The server accepts only known IDs/versions and finite configuration, not source trees or paths. The catalog/factory verifies the pinned manifest and source hashes. Publish a new version for a snapshot change; never rewrite a released version. The catalog reports experimental maturity and concrete limits.

The fresh resource starter allocates a stable loopback frontend port and creates an ignored `0600` output `.env` with random database credentials and the actual API public origin. Existing environment files are preserved. Ambiguous origins, ambient credentials, conflicting ports, unknown provenance and implicit adoption of nonempty output stop before generation writes. If a previously generated output loses its environment, restore it; regeneration will not invent replacement credentials. Later unsupported capabilities may require explicit environment setup. This is local development setup, not a deployment secret manager or an origin migration.

Run `pnpm work run resource-starter` for the bounded disposable proof using the actual starter factory and its private environment. It reuses the generated workspace journey, checks frozen artifacts and zero implementation tasks, preserves custom extras and credentials through preset regeneration, and cleans its own containers/volumes/output. No live qrwty or editor diagram is changed. Broad certification, load/failover, organization roles/SSO and arbitrary workflows remain future work.
